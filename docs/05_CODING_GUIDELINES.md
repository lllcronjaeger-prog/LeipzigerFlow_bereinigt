# Coding Guidelines

- Eine Klasse pro Datei, soweit sinnvoll.
- Type Hints für öffentliche Schnittstellen verwenden.
- Öffentliche Klassen und nicht offensichtliche Methoden dokumentieren.
- Keine SQL-Abfragen in Dialogen.
- Keine Businesslogik in Repositories.
- Validierung und Fachlogik gehören in Services.
- Methoden klein und klar halten; ungefähr 40 Zeilen sind ein Richtwert, kein starres Limit.
- Vollständige Dateien werden einzelnen, kontextlosen Schnipseln vorgezogen.
- Namen und APIs vergleichbarer Module werden einheitlich gehalten.
- Jeder Sprint endet mit einem start- und testbaren Projektzustand.
